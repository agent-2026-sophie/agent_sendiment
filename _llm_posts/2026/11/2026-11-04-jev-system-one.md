> "Jev 类模型并不是直接输出概率，而是从该模型输出可以提取概率。"

这句话的核心是理解 System One 模型的概率生成机制——概率不是模型"生成"出来的文本，而是推理过程中从内部 logits 里"提取"出来的中间量。

---

## 一、前向传播（Forward Propagation）

**一句话：把数据喂进模型，从输入层一路算到输出层，得到结果的过程。**

可以类比成一条流水线：

```
输入文本 → 第1层变换 → 第2层变换 → … → 第N层变换 → 输出结果
```

每一层都做两件事：

1. 拿上一层的输出，乘以一组权重（模型"学"到的参数）
2. 过一个激活函数，把结果传给下一层

这个过程是单向的、从前往后，所以叫"前向"。调用模型 API、模型在 GPU 上跑一次推理，本质上就是在做一次前向传播。

> **对比反向传播（Back Propagation）**：训练模型时，先做一次前向传播得到预测结果，再算预测和真实答案差多少（损失），然后从后往前一层层调整权重——这个"从后往前调参数"的过程叫反向传播。推理（部署上线）只做前向传播，不做反向。

### 在 Jev 场景里

把 `state + question + options` 拼好，通过 chat template 组织成 input ids，送进模型做一次前向传播。模型不需要像普通 LLM 那样一个 token 一个 token 地"生成"输出，而是**一次前向就把所有问题的判断结果都算出来了**。

这也是为什么它快——没有自回归逐 token 解码的开销。

## 二、Logits（对数几率）

**一句话：模型最后一层输出的、还没经过归一化的原始分数，就叫 logits。**

### 1. 它长什么样

语言模型的输出层，本质上是一个**词表大小的向量**。假设词表有 5 万个 token，最后一层输出就是一个包含 5 万个数字的向量，每个数字对应一个 token 的"原始得分"。这个向量就是 logits。

比如在"付款没到账"这个例子里，最后一层输出的某个位置上：

| token | logits 值（原始分数） |
|---|---|
| "billing" | 3.2 |
| "technical" | 1.5 |
| "refund" | 0.8 |
| 其它 49997 个 token | 都很低，比如 -2.0、-3.5 … |

这些数字还不是概率——它们可以是任意实数，可正可负，加起来也不等于 1。

### 2. 为什么叫"对数几率"

Logit 的数学定义：

$$\text{logit}(p) = \log\left(\frac{p}{1-p}\right)$$

其中 $p$ 是概率，$\frac{p}{1-p}$ 就是"几率"（odds），再取个对数就是 logit。它是一个"把概率映射回实数"的函数——概率 $p \in [0,1]$，经过 logit 变换后落到整个实数域 $\mathbb{R}$。

反过来想：模型最后一层输出的那些原始分数（logits），本质上就是在输出"对数几率"。对这些 logits 做一次 softmax，就能把它们变回概率分布。

---

## 三、从 logits 到概率：Softmax

Softmax 的公式：

$$P(\text{token}_i) = \frac{e^{\text{logit}_i}}{\sum_j e^{\text{logit}_j}}$$

作用：把一组任意实数，压缩成加起来等于 1 的概率分布。

还是上面那个例子，如果只看 "billing" 和 "technical" 两个选项：

$$P(\text{billing}) = \frac{e^{3.2}}{e^{3.2} + e^{1.5}} \approx \frac{24.5}{24.5 + 4.5} \approx 0.845$$

$$P(\text{technical}) \approx 0.155$$

这就是 Jev 输出里那个 `probabilities: {"billing": 0.9, "technical": 0.1}` 的来源——**不是模型"写"出来的字符串，而是前向传播最后一层 logits 经过 softmax 算出来的。**

---

## 四、串起来：完整链路

整条概率提取链路是这样的：

1. **输入拼好**：代码把 `state`、`question`、`options`（A/B/C/D 或 billing/technical）按模板拼成 input ids
2. **一次前向传播**：送进模型，算出最后一层的 logits 向量
3. **取对应位置的 logits**：在选项 token 那个位置上，取出 "billing"、"technical" 等几个 token 对应的 logit 值
4. **Softmax 归一化**：只在这几个选项内做 softmax，得到各选项概率
5. **代码组装输出**：把 `choice`、`probabilities`、`confidence` 这些字段填好，返回 JSON

模型从头到尾**没有"生成"过任何概率文本**。概率是推理过程中自然产生的中间量，部署代码只需要把这个中间量读出来就行。

---

## 五、对比总结

| 概念 | 通俗理解 | 在 Jev 里的作用 |
|---|---|---|
| 前向传播 | 数据从输入走到输出的一次计算 | 一次推理就把所有问题的判断算完 |
| Logits | 最后一层输出的原始分数向量 | 选项 token 位置上的分数，直接反映模型倾向 |
| Softmax | 把原始分数变成加起来等于 1 的概率 | 得到各选项的概率分布 |

| 维度 | 传统 LLM | Jev（System One） |
|---|---|---|
| 输出方式 | 逐 token 生成文本，再解析出概率 | 一次前向，从 logits 直接读出概率 |
| 概率来源 | 模型"说"出来的，可能不准 | 模型内部原生输出，结构由代码保证 |
| 格式错误 | 可能 JSON 格式错、字段名漂移 | 由构造保证，0% 类型错误 |
| 延迟 | 随输出字数线性增加 | 极低且稳定（70–500ms） |

---

## 六、关键结论

> **模型侧**："模型不需要去生成概率，或者说不需要生成那个 key，key 就是在代码里面拼好。概率值是可以从模型里面直接拿。"

> **推理部署侧**："实际上是你要把它都给拼好了，然后让模型预测下一个 token 的概率是什么……再去取它的对数。本身这个 key 就不是生成的；是系统就写好了这个 key 必定输出；我们需要的只是填入概率值。"
