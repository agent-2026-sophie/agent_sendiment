## 1. 背景说明

当前讨论的核心问题是：在多轮对话中，模型在上一轮用户请求中产生的内部推理内容，是否会被保留到下一轮用户请求中继续使用。

其中涉及几个关键概念：

- **Turn**：一轮对话，通常可以理解为一次“用户输入 → 模型处理 → 模型回复”的完整交互。
- **CoT / Chain of Thought / Think**：模型在生成答案、调用工具、分析问题时产生的内部推理过程。
- **User CoT**：用户当前轮输入触发的模型内部思考或推理内容。它不是用户自己写出来的内容，也不是用户消息文本，而是模型为了回答该用户问题在后台产生的中间推理。
- **Tool call CoT**：模型在同一轮对话中围绕工具调用产生的内部推理，例如 deciding 调什么工具、如何理解工具结果、下一步如何继续处理等。

---

## 2. “Turn 间 User CoT 会清除”是什么意思

“Turn 间 User CoT 会清除”可以理解为：

> 当前 user turn 完成后，这一轮由用户问题触发的隐藏推理状态不会作为隐藏 CoT 继续保留到下一个 user turn。

更具体地说：

1. 前一个 user turn 中产生的隐藏 CoT 不应跨轮保留；
2. 如果前一个 user turn 内发生了多个 tool call，这些 tool call 前后产生的内部推理也不应作为隐藏 CoT 带到下一个 user turn；
3. 下一轮模型应主要依赖可见上下文，而不是依赖上一轮未显式暴露的内部推理。

需要注意，这里的“清除”并不等于清除全部历史信息。

---

## 3. 哪些内容会清除，哪些内容仍可能保留

### 3.1 会被清除的内容

以下内容原则上不应跨 user turn 保留：

- 上一轮用户问题触发的隐藏推理；
- 上一轮模型内部形成但没有显式输出的中间判断；
- 上一轮模型内部的假设、筛选依据、排除项；
- 上一轮多个 tool call 前后的隐藏思考；
- 上一轮未写入最终回答的工具使用计划或后续计划。

### 3.2 仍可能保留的内容

以下内容不是 CoT 清除对象，下一轮仍可能被模型看到和使用：

- 用户之前显式说过的话；
- assistant 之前显式输出过的最终回答；
- 工具返回并被纳入可见上下文的结果；
- 被 assistant 总结进最终回答中的工具结果、结论或步骤。

因此，跨 turn User CoT 清除并不等于“模型完全忘记上一轮”。它只是清除隐藏推理状态，不清除普通对话上下文。

---

## 4. 为什么要用多轮 user 评估集考察

如果要评估“跨 turn User CoT 是否被清除”，核心评估集必须是多轮 user-turn case。

原因如下：

1. **“跨 turn”本身要求至少两个 user turn**  
   第一轮用于触发模型内部推理，第二轮用于观察模型是否还能依赖上一轮隐藏推理。

2. **单轮评估无法验证跨轮清除**  
   单轮评估只能观察同一轮中的推理连续性，例如 tool call 前后的处理是否一致，无法判断上一轮隐藏 CoT 是否被带入下一轮。

3. **需要区分隐藏 CoT 与可见上下文**  
   如果下一轮模型答对了，需要判断它是基于上一轮可见文本答对，还是基于上一轮未显式输出的隐藏 CoT 答对。

---

## 5. 推荐的评测设计

### 5.1 正向验证清除

设计思路：

1. Turn 1：诱导模型在内部推理中得到某个中间结论；
2. 但要求模型最终回答时不要显式输出该中间结论；
3. Turn 2：追问一个依赖该中间结论的问题；
4. 期望结果：模型不能凭空使用上一轮未输出的隐藏 CoT。

如果模型在 Turn 2 中准确使用了 Turn 1 未显式输出的信息，就可能说明隐藏 CoT 被跨轮保留，或者评测样本存在信息泄露。

### 5.2 对照验证 Turn 内保留

设计思路：

1. 在同一个 user turn 内触发多步推理或多个 tool call；
2. 观察模型是否能在同一轮中连续使用 tool call 前后的推理；
3. 期望结果：同一轮内的 tool call CoT 可以服务于当前任务。

这类 case 用于区分：

- 跨 user turn 的 CoT 应清除；
- 同一 user turn 内的工具调用相关推理可以保留。

---

## 6. 为什么保留或删除历史 User CoT 会影响模型效果

历史 User CoT 不是普通上下文，而是模型上一轮形成的中间判断、假设、计划和隐含状态。保留或删除它，会改变下一轮模型可用的信息和推理起点。

### 6.1 信息量变化

如果保留历史 CoT，下一轮模型可能拿到上一轮没有显式输出的中间结论，例如：

- 筛选依据；
- 排除项；
- 工具调用计划；
- 隐含变量；
- 未写进最终答案的计算过程。

删除后，模型只能依赖用户和 assistant 的可见上下文，以及当前轮重新推理。

### 6.2 任务连续性变化

保留 CoT 时，多轮复杂任务可能更连续，因为模型可以接着上一轮内部计划继续执行。

删除 CoT 后，模型需要从显式上下文恢复任务状态。如果上一轮最终回答没有把关键状态写清楚，下一轮可能丢失方向。

### 6.3 错误传播风险变化

保留 CoT 不只会保留正确推理，也可能保留错误假设。

如果上一轮内部推理中存在误判，下一轮可能继续沿着错误方向推进，形成“惯性错误”。删除历史 CoT 可以降低隐藏错误跨轮污染的风险。

### 6.4 评测结果变化

如果评测题的关键信息只存在于上一轮 CoT 中，而不在可见文本中，那么：

- 保留 CoT 的模型可能答对；
- 删除 CoT 的模型可能答不出；
- 同一个多轮评测集在两种策略下可能表现不同。

### 6.5 隐私与合规影响

CoT 可能包含模型对用户意图、敏感信息、工具结果的内部归纳。

跨轮保留会扩大这些隐含信息的生命周期和影响范围。删除历史 CoT 有助于降低非预期泄露和跨任务干扰风险。

---

## 7. 核心结论

可以总结为：

> 跨 turn User CoT 清除，是指一个 user turn 结束后，该轮内部产生的隐藏推理状态，包括多个 tool call 前后的隐藏推理，不应继续作为隐藏 CoT 保留到下一个 user turn。

但它不等于清除所有历史上下文。下一轮仍可能使用上一轮的可见用户输入、assistant 输出，以及被纳入上下文的工具结果。

评估这一策略时，必须使用多轮 user-turn 评估集，并且要严格控制上一轮最终可见输出，避免把可见上下文带来的正确回答误判为隐藏 CoT 保留。

最终权衡是：

> 保留历史 User CoT 可能增强隐式记忆和连续推理能力，但会增加错误继承、隐私暴露和评测污染风险；删除历史 User CoT 更安全、边界更清晰，但可能降低依赖隐式状态的多轮任务表现。
