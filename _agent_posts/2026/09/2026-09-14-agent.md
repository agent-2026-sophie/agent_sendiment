# Agent 场景下模型如何读取、理解和生成 PDF、DOC、XLSX、PPTX 等文件

在 **Agent 场景**下，模型通常不是“直接读懂二进制文件本身”，而是通过一套 **文件解析工具 + 结构化中间表示 + 多模态/文本理解 + 文件生成工具** 来读取、理解和生成 PDF、DOC/DOCX、XLSX、PPTX 等文件。

## 1. 总体流程

典型链路是：

1. **接收文件**
   - 用户上传 PDF、Word、Excel、PPT 等文件。
   - Agent 获取文件路径、类型、大小、页数等元信息。

2. **文件解析**
   - 调用对应解析器，把文件内容转成模型可理解的形式：
     - 文本
     - 表格
     - 图片
     - 页面布局
     - 标题层级
     - 批注、修订、备注等元信息

3. **结构化表示**
   - 将原始文件转换成类似 Markdown、JSON、HTML、表格矩阵、页面对象树等中间格式。
   - 模型主要基于这些结构化内容进行理解。

4. **模型理解与推理**
   - 模型对提取出的内容做摘要、问答、信息抽取、对比、改写、分类、数据分析等。

5. **生成或修改文件**
   - 如果用户需要输出 PDF、DOCX、XLSX、PPTX，Agent 会使用文档生成工具或办公文件库，把模型生成的内容重新写入目标格式。

---

## 2. 不同文件类型如何处理

### PDF

PDF 的核心特点是：**更像“打印后的页面”，不一定有良好的语义结构**。

Agent 通常会这样处理：

- **文本型 PDF**
  - 直接提取页面中的文字、段落、表格、标题。
  - 尽量保留页码、章节、布局关系。

- **扫描版 PDF / 图片型 PDF**
  - 先做 OCR，把图片中的文字识别出来。
  - 如果包含表格，还需要表格识别。
  - 如果有图表，可能需要视觉理解或截图分析。

- **理解方式**
  - 按页读取。
  - 对长 PDF 分块处理。
  - 建立章节、标题、页码和内容之间的映射。

- **生成方式**
  - 通常先生成 Markdown、HTML 或 DOCX，再导出为 PDF。
  - 如果要求固定版式，则需要专门的排版引擎。

适合任务包括：合同审阅、论文总结、报告抽取、发票/单据识别、PDF 转 Word、长文档问答等。

### DOC / DOCX

Word 文档的结构通常比 PDF 更语义化。

Agent 可以读取：

- 标题层级
- 正文段落
- 表格
- 图片
- 页眉页脚
- 脚注尾注
- 批注
- 修订痕迹
- 样式信息

处理方式通常是：

1. 解析文档 XML 结构。
2. 提取段落、标题、表格、批注等对象。
3. 转换成 Markdown 或结构化 JSON。
4. 模型进行理解、改写、润色、审阅。
5. 再写回 DOCX，尽量保留格式。

适合任务包括：文档润色、合同修订、报告生成、批注处理、格式保持编辑、模板填充等。

### XLSX

Excel 文件本质上是 **工作簿 + 工作表 + 单元格 + 公式 + 样式 + 图表**。

Agent 读取时通常会关注：

- 工作簿结构
- Sheet 名称
- 单元格区域
- 表头
- 数据类型
- 公式
- 合并单元格
- 筛选器
- 数据透视表
- 图表
- 条件格式

理解方式分两类：

#### 1. 表格语义理解

例如：

- 哪一行是表头
- 哪些列是维度
- 哪些列是指标
- 是否存在时间字段
- 是否有空值、异常值、重复值

#### 2. 数据计算分析

例如：

- 汇总
- 分组
- 排序
- 透视
- 增长率
- 同比/环比
- 相关性分析
- 显著性检验
- 可视化

生成方式包括：

- 创建新 Excel
- 写入多 Sheet
- 添加公式
- 设置样式
- 生成图表
- 导出 CSV
- 转成飞书表格或数据库表

适合任务包括：经营分析、财务表处理、数据清洗、报表自动化、批量核对、模型分数统计等。

### PPTX

PPTX 不是连续文档，而是 **页面级画布**。

Agent 读取时通常会解析：

- 幻灯片顺序
- 每页标题
- 文本框
- 图片
- 表格
- 图表
- 形状
- 备注
- 母版样式
- 布局关系

理解时会关注：

- 每页主题
- 页面层级
- 视觉结构
- 文案逻辑
- 图文对应关系
- 整体叙事线

生成方式通常是：

1. 先生成大纲。
2. 拆成每页 slide。
3. 为每页生成标题、要点、图表建议和讲稿。
4. 使用 PPTX、HTML Slides 或飞书文档工具渲染。
5. 设置主题、字体、颜色、版式。

适合任务包括：汇报材料、项目复盘、路演材料、技术分享、培训课件、商业计划书等。

## 3. 模型“理解文件”的本质

模型本身擅长理解 **文本、结构化数据、图片描述和上下文关系**。  
所以 Agent 会把复杂文件转成模型更容易处理的中间表达，例如：

- Markdown：适合长文档、报告、PPT 大纲。
- JSON：适合结构化字段、表格、批注、元数据。
- CSV/DataFrame：适合 Excel 数据分析。
- 图片或页面截图：适合版式、图表、扫描件理解。
- HTML：适合保留布局和生成演示文稿。
- 文档对象模型：适合精确编辑 Word/PPT。

可以理解为：

> Agent 不是让模型直接“看懂 Word/PDF 二进制”，而是先把文件拆解成可读、可推理、可编辑的结构，再由模型完成理解和生成。

---

## 4. 长文件如何处理

对于大文件，Agent 通常不会一次性把全部内容塞给模型，而是采用：

1. **分页读取**
   - PDF 按页处理。
   - PPT 按 slide 处理。
   - Word 按章节处理。
   - Excel 按 sheet 或数据区域处理。

2. **分块摘要**
   - 每一块先生成局部摘要。
   - 再合并成全局摘要。

3. **索引检索**
   - 为文档建立向量索引或关键词索引。
   - 用户提问时只检索相关片段。

4. **结构化抽取**
   - 先抽出标题、目录、表头、关键字段。
   - 再进行针对性分析。

这可以避免上下文过长、成本过高、遗漏关键信息。

## 5. 生成文件时怎么保证质量

生成 PDF、DOCX、XLSX、PPTX 时，一般会分为两层：

### 内容层

由模型负责：

- 结构规划
- 文案撰写
- 摘要改写
- 数据解释
- 标题生成
- 逻辑组织

### 格式层

由工具负责：

- 页面布局
- 样式设置
- 字体字号
- 表格合并
- 图片插入
- 图表绘制
- 文件导出
- 模板套用

这样可以避免模型直接“想象格式”，而是通过确定性工具生成真实可打开的文件。

## 6. 常见能力边界

需要注意几个限制：

1. **扫描件质量影响 OCR**
   - 图片模糊、倾斜、遮挡会影响识别准确率。

2. **PDF 表格恢复较难**
   - PDF 中的表格不一定有真实单元格结构，可能只是视觉排版。

3. **复杂 Excel 公式可能需要执行环境**
   - 有些公式、宏、外部链接、数据透视表需要专门计算引擎。

4. **PPT 视觉设计需要模板或设计规则**
   - 模型能生成内容，但高级排版通常依赖模板、设计系统或专门渲染工具。

5. **格式保持不是天然保证**
   - 修改 Word/PPT 时，若要求完全保持原格式，需要基于原始文档结构做精细编辑。

6. **大文件需要分块**
   - 超长文件通常需要分页、检索或分阶段处理。

## 7. 在企业 Agent 中的典型架构

一个比较完整的文件处理 Agent 通常包含：

1. **文件接入层**
   - 上传、下载、权限校验、病毒扫描、格式识别。

2. **解析层**
   - PDF parser
   - OCR
   - DOCX parser
   - XLSX parser
   - PPTX parser

3. **结构化层**
   - Markdown 转换
   - JSON Schema
   - 表格 DataFrame
   - 页面布局树

4. **理解层**
   - 摘要
   - 问答
   - 信息抽取
   - 数据分析
   - 语义检索

5. **生成层**
   - DOCX 生成
   - XLSX 生成
   - PPTX/HTML slides 生成
   - PDF 导出

6. **安全合规层**
   - 权限控制
   - 敏感信息识别
   - 数据脱敏
   - 操作审计
   - 文件访问隔离

## 8. 简单例子

如果用户说：

> 帮我总结这个 80 页 PDF，并提取其中所有风险项，输出成 Excel。

Agent 的实际执行可能是：

1. 读取 PDF 页数和文本。
2. 如果是扫描件，先 OCR。
3. 按章节分块。
4. 每块提取风险项。
5. 合并去重。
6. 形成结构化字段：
   - 风险名称
   - 所在页码
   - 风险描述
   - 影响范围
   - 建议措施
   - 原文引用
7. 写入 XLSX。
8. 返回下载链接或上传到企业文档系统。

---

## 9. 一句话总结

**Agent 处理 PDF、DOC、XLSX、PPTX 的核心不是让模型直接读取文件格式，而是通过工具把文件解析成文本、表格、图片和结构化对象，模型负责理解与推理，再由工具把结果写回目标文件格式。**
