## 1. 什么是 Base64 编码

**Base64 编码**是一种把二进制数据转换成可打印文本的编码方式，常用于在只支持文本的场景中传输图片、文件、密钥片段等数据。

简单理解：

> Base64 会把原始数据按 6 位一组重新切分，并映射成 64 个可见字符。

常见字符集包括：

- 大写字母：`A-Z`
- 小写字母：`a-z`
- 数字：`0-9`
- 符号：`+`、`/`
- 填充符：`=`

例如：

`Hello` 的 Base64 编码是：

`SGVsbG8=`

需要注意：

1. **Base64 不是加密**，任何人都可以轻松解码。
2. 编码后体积通常会变大，大约增加 **33%**。
3. 常见用途包括：邮件附件、Data URL、JSON 中传输二进制内容、Basic Auth 等。

## 2. Base64 为什么可以把本地文件夹转换成一个字符串

严格来说，**Base64 不能直接把“文件夹”转换成字符串**。

它能做的是：

> 把一段**二进制数据**编码成一段**文本字符串**。

所以“把本地文件夹变成一个 Base64 字符串”通常分两步：

1. **先把文件夹打包成一个单一文件**
   - 例如 `.zip`、`.tar`、`.tar.gz`
   - 这个打包文件会包含：
     - 多个文件的内容
     - 文件名
     - 子目录结构
     - 部分元数据，如权限、时间戳等，取决于打包格式

2. **再把这个打包文件的二进制内容做 Base64 编码**
   - 得到一个很长的字符串
   - 这个字符串可以放进 JSON、文本文件、HTTP 请求体等文本环境中传输

流程可以理解为：

```text
本地文件夹
  ↓ 打包
archive.zip
  ↓ 读取为二进制
010101...
  ↓ Base64 编码
UEsDBBQAAAA...
```

解码时反过来：

```text
Base64 字符串
  ↓ Base64 解码
archive.zip
  ↓ 解压
原来的文件夹
```

所以关键点是：

**Base64 编码的对象不是文件夹本身，而是“文件夹打包后形成的那个二进制文件”。**

如果不先打包，Base64 只知道如何编码一串字节，并不知道：

- 文件夹里有几个文件
- 文件名是什么
- 子目录结构是什么
- 哪段字节属于哪个文件

这些信息必须由 `.zip` / `.tar` 这类归档格式来保存。

## 3. 大文件夹或数据库是否适合用 Base64 转字符串

如果本地文件夹非常大，比如包含几个 GB 的数据库，那么用 Base64 转换出来的字符串会**非常长**。

Base64 会把二进制数据按规则转换成文本，编码后的体积大约是原始二进制的 **4/3**，也就是增加约 **33%**。

例如：

- 原始压缩包：`1 GB` → Base64 后约 `1.33 GB`
- 原始压缩包：`5 GB` → Base64 后约 `6.67 GB`
- 原始压缩包：`10 GB` → Base64 后约 `13.33 GB`

所以如果本地文件夹里有几个 GB 的数据库，即使先打包，再 Base64，最终字符串也会是**数十亿到上百亿字符级别**。

实际问题包括：

1. **内存压力很大**
   - 很多程序会试图一次性把字符串读进内存，容易 OOM。

2. **传输效率低**
   - Base64 比原始二进制更大，上传下载更慢。

3. **存储成本增加**
   - 文本体积更大，占用更多磁盘或数据库空间。

4. **处理不方便**
   - 日志、JSON、接口请求、剪贴板、编辑器都不适合承载几 GB 的字符串。

5. **数据库文件本身可能不适合直接打包**
   - 如果数据库正在运行，直接复制数据库文件可能得到不一致的数据。
   - 更推荐使用数据库自带的备份 / dump / snapshot 机制。

更合理的做法通常是：

1. **先做数据库备份或导出**
   - 例如 dump、snapshot、backup 文件。

2. **压缩**
   - 如 `tar.gz`、`zip`、`zstd`。

3. **分片上传或对象存储**
   - 上传到 S3、OSS、TOS、云盘等。
   - 只传一个下载链接或文件 ID。

4. **必要时再做校验**
   - 用 SHA-256 / MD5 校验文件完整性。

结论：**Base64 适合小型二进制数据嵌入文本，不适合几个 GB 的数据库或大文件夹传输。**

## 4. Encode 示例代码：文件夹打包并转为 Base64 字符串

下面代码会将 `case-001` 文件夹打包为 `case-001.zip`，然后把 zip 文件编码为 Base64 字符串，写入 `instance_data.txt`。

```python
from pathlib import Path
import base64
import zipfile

root = Path("case-001")
zip_path = Path("case-001.zip")

with zipfile.ZipFile(
    zip_path,
    "w",
    compression=zipfile.ZIP_DEFLATED,
    compresslevel=9,
    allowZip64=True,
) as zf:
    for path in sorted(root.rglob("*")):
        if path.is_file():
            zf.write(path, path.relative_to(root).as_posix())

instance_data = base64.b64encode(
    zip_path.read_bytes()
).decode("ascii")

Path("instance_data.txt").write_text(instance_data)
```

## 5. Decode 示例代码：Base64 字符串还原为 zip 文件

下面代码会读取 `instance_data.txt` 中的 Base64 字符串，将其解码回二进制内容，并写入 `restored.zip`。

```python
import base64
from pathlib import Path

raw = base64.b64decode(
    Path("instance_data.txt").read_text(),
    validate=True,
)

Path("restored.zip").write_bytes(raw)
```

如果需要恢复原始文件夹，还需要再解压 `restored.zip`。

## 6. 总结

- Base64 的本质是：**二进制数据 ↔ 文本字符串**。
- 文件夹不能被 Base64 直接编码，必须先被打包成 `.zip` / `.tar` 等单一二进制文件。
- Base64 编码后体积会增加约 **33%**。
- 对于大文件夹、大数据库，不建议直接使用 Base64 字符串传输。
- 更推荐使用：数据库备份、压缩、分片上传、对象存储、校验哈希等方式。
